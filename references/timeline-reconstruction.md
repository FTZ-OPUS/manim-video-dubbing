# 从 Manim 源码重建时间轴

时间轴的唯一权威来源是渲染源码。绝不靠目测抽帧建段落表——读帧只做抽查与漂移定位。

## 1. 段落划分：以 construct() 调用顺序为准

- `construct()` 方法体里的 `self.xxx()` 调用顺序 = 播放顺序 = 段落顺序。**方法在文件中的定义顺序可能与此不同**（实测出现过定义靠后、调用在前的情况），必须抄 construct 的调用清单。
- 源码可能在一段里通过辅助方法嵌套播放完整"子页"（如自定义 `f_page(...)` 辅助：先写标题栏、逐行写内容、停顿、清屏）——这类子页是独立段落，要展开计算。识别方法：通读源码时留意所有会调用 `self.play` 的辅助方法。

## 2. helper 语义：必须读基类/文件内定义确认，不能凭记忆

不同项目 helper 参数不同，逐文件确认。常见模式（值以各项目实际定义为准）：

| helper | 展开 |
|---|---|
| `write_formula(mob, rt)` | play(Write, rt) + wait(READ_PAUSE) |
| `wait_formula()` | wait(READ_PAUSE) |
| `write_text(mob, rt)` | play(Write, rt)（无停顿） |
| `clear_scene()` | play(FadeOut×, 0.5)，每段结尾一次 |
| `move_camera(..., run_time=0.1)` | 也是一次 play（3D 场景） |
| `self.add(m)` / `begin_ambient_camera_rotation()` | 不耗时 |

`READ_PAUSE` 各项目不同（实测见过 1.6 / 2.2 / 2.5），只认文件里的定义。

## 3. 逐段累加与硬自检

- 段落起点 = 该段第一个 play 之前所有动画时长之和
- **硬自检**：全片累加总和 vs `ffprobe` 实际时长。60/30fps 下 run_time 多为 0.05 的倍数，理论无舍入损失；误差 ≤0.5s 视为通过
- 自检差值**无论正负都必须解释**：渲染版可能比源码短（某 wait 被改短）也可能长（收尾停顿加长）；且漂移往往**非均匀**——实测 +2.36s 中 2.1s 集中在 2/14 段
- 可选二次对账：`media*/videos/<场景>/<分辨率>/partial_movie_files/<场景>/` 每个分段文件对应一次 play/wait，逐个 ffprobe 累加即精确时间轴（渲染产物常被清理，找不到就走帧定位）

## 4. 漂移定位（自检差值 >0.5s 时的标准动作）

1. 按模型边界放探针：抽**单张全分辨率帧**（如 `ffmpeg -ss <边界+0.4> -i video -frames:v 1`），判读三态：
   - 该段标题栏（0.8s Write）**正在写一半** → 边界正确
   - **上一段内容完整可见**（保持态）→ 实际边界更晚
   - **已出现下一段内容 / 全屏变暗**（FadeOut 中）→ 实际边界更早
2. 从探针反推该段实际时长，修正边界；其后所有边界随之平移，用后续探针验证
3. 循环直到**首、中、尾**三点帧证据全部闭合
4. 经验：漂移常集中在少数几段的收尾 wait；首个探针必验证片头边界

## 5. 抽帧纪律

- 只抽**单张全分辨率帧**，拒用密集拼图/接触表（小格易误读、易把 A 段看成 B 段）
- 低阈值 `select=scene` 场景检测对 Manim 渐变动画完全失效（逐帧差异永远低于阈值），不要尝试
- 读帧结果自相矛盾时停止"调和矛盾"——回到源码重新推演或向用户求证
